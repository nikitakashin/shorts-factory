# Свой YouTube-канал: SEO загруженных роликов и аналитика

Схема работы с автором: **он загружает ролик в Студии** (файл, дата публикации, обложка), **ты дописываешь текст** — название,
описание и теги из `youtube.md`, который уже прошёл `just-another-youtube-seo-generator` (`validate.py`). И по запросу — аналитика.

Скрипт: `Y=<путь к скиллу>/scripts/yt.py`, запуск `uv run --script $Y <команда>` (зависимости ставятся сами).

## Правила

- **Любая запись на канал — только после явного «да» автора в чате.** Это публикация: `plan` показывает было/стало,
  автор подтверждает, только тогда `apply … --yes` (и `thumb … --yes`). Одно «да» — на один показанный план, не на будущие.
- `apply` сверяет ролик с планом: если его поменяли в Студии после `plan`, ролик пропускается — пересобери план.
- Правка перезаписывает блок snippet целиком, поэтому план собирается из текущих данных ролика: меняются только название,
  описание и теги; категория и язык остаются, **дата выхода и статус не трогаются** (правится только snippet).
- Текст бери из проверенного `youtube.md`, а не пиши заново: факты и хештеги там уже сверены с данными поиска.
- Аналитику YouTube отдаёт с задержкой ~2–3 дня: последние дни неполные, так и говори.

## Настройка (один раз, делает автор; ключи и пароли в чат не просить)

1. console.cloud.google.com → проект, где уже есть ключ YouTube Data API (или новый).
2. «APIs & Services» → «Library»: включить **YouTube Data API v3** и **YouTube Analytics API**.
3. «Google Auth Platform» (бывший «OAuth consent screen»): имя приложения и почта; аудитория **External**; в «Audience» добавить свою
   почту в **Test users**. В тестовом режиме вход живёт 7 дней — потом `auth` заново. Чтобы не слетал: «Audience» → **Publish app**
   (проверка Google для личного пользования не нужна; при входе будет экран «Google hasn't verified this app» → Continue).
4. «Clients» → «Create client» → тип **Desktop app** → скачать JSON → положить как `~/.config/yt-seo/client_secret.json`.
5. `uv run --script $Y auth` — откроется браузер: автор выбирает аккаунт (если канал — бренд-аккаунт, выбрать именно канал)
   и разрешает доступ. Токен — `~/.config/yt-seo/token-<профиль>.json` (`chmod 600`).
   **Несколько каналов:** профиль = имя папки канала в `~/Movies/Shorts/` (`ai-native` — по умолчанию, `syamych`…), вход на каждый —
   `auth --profile <канал>`. `plan <папка ролика>` берёт профиль из папки канала сам; остальные команды — `--profile` или `$YT_PROFILE`.
   Бренд-канал в окне выбора аккаунта Google может называться старым именем бренда, а не текущим названием канала: после входа проверяй `whoami`.
6. `uv run --script $Y whoami` — проверить, что подключён нужный канал.

Права: `youtube.force-ssl` (свои ролики: чтение и правка) и `yt-analytics.readonly`. Квота: правка ролика — 50 единиц
из 10 000 в сутки (≈ 200 правок в день), чтение — 1 единица за запрос.

## Сценарии

**Автор залил ролик — дописать SEO:**
```bash
uv run --script $Y plan "$ПАПКА"     # ролик из adhd-shorts: файл назван как папка (2026-10-21-ask-expert-2.mp4), YouTube взял это черновым
                                     # названием → скрипт находит ролик сам, берёт $ПАПКА/youtube.md, план — в $ПАПКА/.work/yt_plan.json
# иначе — найти вручную и указать id:
uv run --script $Y videos --status scheduled --limit 10      # (или --grep "кусок названия", --since 2026-10-20)
uv run --script $Y plan <id> "$ПАПКА/youtube.md" --out "$ПАПКА/.work/yt_plan.json"
# показать автору вывод plan (было → стало) и закреп; после «да»:
uv run --script $Y apply "$ПАПКА/.work/yt_plan.json" --yes
```
Закреп API закрепить не умеет: отдай автору текст из вывода `plan`, он вставит и закрепит в Студии в один клик.
После `apply` по плану из папки ролика статус папки становится «выгружен», и она переезжает в `~/Movies/Shorts/<канал>/Archive/`
(`adhd-shorts/scripts/status.py`).

**Обложка:** `uv run --script $Y thumb <id> "$ПАПКА/cover_A.jpg" --yes` (после «да»; файл до 2 МБ — `.jpg` из `cover_gen.py`;
у канала должен быть подтверждён телефон).

**Массовая правка старых роликов:** собери `правки.json` — `[{"id": "…", "title": "…", "description": "…", "tags": ["…"]}]`
(любое поле можно опустить — оно останется как есть), каждую правку прогони через `validate.py` SEO-скилла, затем
`plan --batch правки.json` → показать автору → `apply … --yes`.

**Аналитика:**
```bash
uv run --script $Y analytics --preset videos --start 2026-09-22 --end 2026-10-20 --out отчёт.csv   # по роликам, с названиями
uv run --script $Y analytics --preset daily|traffic|countries|devices|subscribed|shorts
uv run --script $Y analytics --metrics views,averageViewPercentage --dimensions video --filters "video==ID1,ID2" --sort=-views
```
Пресеты: `videos` (по роликам: просмотры, минуты, средняя длительность и процент досмотра, лайки, репосты, комментарии,
подписки), `daily` (по дням), `traffic` (источники трафика), `countries`, `devices`, `subscribed` (подписчики / нет),
`shorts` (Shorts / длинные / эфиры). Не все сочетания метрик и разрезов API разрешает: при ошибке убери метрику или разрез. Сортировка по убыванию — только через `=`
(`--sort=-views`): иначе argparse примет `-views` за флаг.

**Какие метрики есть у канала:** `uv run --script $Y probe-metrics` — проверяет по одной. Итог на канале автора (2026-10-22):
есть `views`, `engagedViews`, минуты, средняя длительность и процент досмотра, лайки, репосты, комментарии, подписки, `redViews`;
**нет** показов и CTR обложки (`videoThumbnailImpressions*` — «query is not supported»).
**«Продолжили смотреть» (главная метрика Shorts в Студии) = `engagedViews / views`** — сверено с выгрузкой Студии по 4 шортсам:
расхождение 0–3 п. (разные периоды), досмотр `averageViewPercentage` совпал точно. `analytics` сам добавляет колонку `stayedPct`,
когда в метриках есть `views` и `engagedViews` (пресет `videos` — уже).

## Чего нет

- **Загрузки новых видео.** Ролики, загруженные через API из проекта Google Cloud без аудита Google, закрываются как
  приватные (документация `videos.insert`), и по сторонним гайдам их нельзя открыть даже в Студии. Поэтому загружает автор
  в Студии (или ты — через Студию в его Chrome, с его «да» на каждую публикацию).
- Закрепа комментария, конечных заставок, подсказок и «Связанного видео» у шортса — этого в API нет, только Студия.
- Чужих каналов: аналитика и правка — только по подключённому каналу.
