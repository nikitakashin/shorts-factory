# SEO для YouTube по фактам, а не по догадкам

Название, описание, хештеги и теги ищут, а не пересказывают сценарий. Поэтому каждый термин в пакете должен найтись в данных:
в подсказках поиска YouTube, в названиях, тегах и хештегах роликов из топа или в самом ролике (расшифровка). Чего там нет, того нет и в пакете.

Три правила:
1. **Данные вместо головы.** Сначала `research.py`, потом текст. Без `seo_research.md` пакет не пишем.
2. **Пишем под поиск, а не пересказ.** Главный ключ — то, что человек набирает, чтобы найти такой ролик. Он в начале названия и в первых 150 символах описания.
3. **Честно о границах.** Скрипты показывают, что используют ролики из топа. Эффект хештега или тега они не измеряют, и YouTube не публикует частоту запросов. Не обещай «это даст охват».

Справочники:
- `references/rules.md` — лимиты YouTube, правила проекта и что сказано в разобранных источниках, с пометкой надёжности. Перед написанием текста.
- `assets/seo.example.json` — образец пакета.

Скрипты: `S=<путь к скиллу>/scripts`.

## Что нужно

- `uv` (зависимости скриптов ставит сам), Python 3.11+.
- **Без ключа:** `yt-dlp` (`brew install yt-dlp`). Поиск yt-dlp не знает языка и страны, поэтому для кириллических языков скрипт отбрасывает ролики,
  где кириллицы меньше 40 % букв (без этого на «как войти в айти» пришли английские шортсы про Cisco). Работает всегда, но у YouTube есть защита от ботов: после десятков заходов на страницы роликов она просит войти, и теги с описаниями конкурентов не приходят. Тогда отчёт честно пишет «детали только у N%». Лечится ключом API или `--cookies-from-browser chrome`.
- **С ключом (необязательно, лучше):** YouTube Data API v3.
  - Получить: console.cloud.google.com → создать проект → включить «YouTube Data API v3» → «Учётные данные» → «API-ключ».
  - Передать: файл `~/.config/yt-seo/key` (скрипт находит сам, `chmod 600`), переменная `YOUTUBE_API_KEY` (например, в `~/.zshenv`), `--key-file <файл>`
    или строка `YOUTUBE_API_KEY=…` в `.env` (ближайший от текущей папки вверх до домашней, или `--env-file`). Порядок: переменная → `--key-file` →
    `~/.config/yt-seo/key` → `.env`. Ключ нигде не печатается и не сохраняется; в репозиторий не клади.
  - Цена: ≈ 200 единиц квоты на каждый запрос (две выборки поиска по 100) плюс ~5 на детали; суточно 10 000, то есть около 45 запросов в день.
  - Что даёт сверх режима без ключа: теги и описания всех конкурентов, лайки, число подписчиков канала, ролики-«выбросы» (просмотров намного больше, чем подписчиков), точную дату.
  - Нет нужного ключа или он отклонён — скрипт сам переходит на yt-dlp.

## vidIQ (необязательно)

У vidIQ есть MCP-сервер (`https://mcp.vidiq.com/mcp`): он даёт агенту данные vidIQ без квоты YouTube Data API. Вход через OAuth в аккаунте vidIQ (в Claude: Connectors → vidIQ → Connect).
По справке vidIQ (support.vidiq.com, статья «vidIQ MCP») MCP доступен на всех тарифах, включая Free; сторонние обзоры, где он «только Max», расходятся с ней.
Кредиты: поиск ключевых слов, аутлайеры, статистика, транскрипты, оценка заголовков — 5 за вызов; анализ Shorts — 10; полный анализ длинного видео — 25; обновление названия, описания, тегов — 5; список конкурентов, баланс и подключённые каналы — бесплатно.
В бесплатном тарифе 150 кредитов в месяц, то есть около 30 исследовательских вызовов; неиспользованные не переносятся.
Подключение: в Claude — каталог коннекторов → vidIQ → Connect (урезанный набор: без правки видео и генерации) или Customize → Connectors → Add custom connector с URL `https://mcp.vidiq.com/mcp` (полный набор). Для Claude Code справка команды не даёт, только URL по стандартному MCP. API-ключ (app.vidiq.com → Account Settings → MCP) нужен для Cursor, VS Code и подобных, а правка видео работает только через OAuth.
TikTok не поддерживается, YouTube и Shorts — да.
Что берём:
- Инструмент поиска ключевых слов (в справке он назван по функции, точные имена инструментов и поля ответа там не приведены; в описании на vidiq.com/mcp — `keyword_research`, с объёмом поиска и конкуренцией) → **объём и конкуренция** по главному ключу и 3–5 лучшим подсказкам. Это единственное, чего нет у нас: частота запросов. Оценки закрыты методикой vidIQ, считай их ориентиром, а не фактом.
- `outliers` → ролики ниши с просмотрами много выше нормы канала: смотреть паттерн названия и упаковки.
- `video_transcript` → расшифровки роликов из топа, чтобы увидеть, какие подтемы они раскрывают.
- Свой канал (после публикации): удержание, источники трафика, поисковые запросы → сравнить варианты упаковки (петля обратной связи, которой нет в коде).
Чего **не** берём: `generate_titles` и другие генераторы текста (это снова текст «из головы»; если взял, пропусти через `validate.py` как любой другой вариант) и массовую правку метаданных без подтверждения пользователя. Правка названия, описания и тегов уже опубликованного видео через MCP возможна (5 кредитов, только OAuth, с показом изменения и подтверждением): это публикация, делать только по явной просьбе пользователя и после `validate.py`.

**Бюджет и порядок (2026-10-22).** Бесплатный тариф — 150 кредитов в месяц, почти всё стоит 5: **30 вызовов, один на ролик** при ролике
в день. Поэтому:
- **На ролик — один `vidiq_keyword_research`** (`mode: research`, `country: RU` или страна аудитории) по **лучшему кандидату в главный ключ**,
  и только **после** бесплатного `research.py`: кандидат — фраза из «Что люди набирают», которую ролик закрывает. Ответ даёт запросы
  в месяц, конкуренцию и рост и по ключу, и по ~20 связанным фразам — из них и выбирается главный ключ по реальному спросу.
- **Сначала кэш** (повторные темы бесплатны, 30 дней):
  ```bash
  python3 $S/vidiq_cache.py get "<ключ>" --out $WD/seo/vidiq.json || echo "нужен вызов"
  # нет в кэше → вызови vidiq_keyword_research, сохрани ответ целиком в файл, затем:
  python3 $S/vidiq_cache.py put "<ключ>" <ответ.txt> --out $WD/seo/vidiq.json
  uv run --script $S/research.py "<ключ>" … --out $WD/seo --vidiq-keywords $WD/seo/vidiq.json   # таблица «vidIQ: сколько ищут в месяц»
  ```
  Учёт: `vidiq_cache.py usage` (вызовы за 30 дней), точный остаток — `vidiq_balance` (бесплатно).
- **Не дёргать:** `outliers` — русские Shorts он не ищет (не-английские — только длинные); `score_title`, `generate_*` — мнение модели,
  а не данные; статистика своих роликов и канала — бесплатно через скилл `youtube-channel` (там же «Продолжили смотреть»).
- **Остаток в конце цикла** (роликов вышло меньше 30) — `keyword_research` с `mode: rising`, `language: ru`: растущие запросы для поиска тем.
- `volume` в сыром ответе — балл 0–100; запросы в месяц — `estimatedMonthlySearch`, `0` там значит «меньше 750», а не ноль.
  Первый вызов (2026-10-22): «как войти в айти» — <750 в месяц, «как войти в it» — 4 339, «работа в it» — 11 972.
Фразы vidIQ попадают в отчёт отдельной таблицей и считаются подтверждением для валидатора.

## Конвейер

### 1. Вход
Нужны: тема и содержание ролика, формат (`shorts` по умолчанию | `long`), язык и страна (по умолчанию `ru`/`RU`) и **расшифровка ролика**
(для adhd-shorts это `$WD/words_out.json`). Расшифровка — единственный источник фактов о самом ролике: бренды, версии, цифры, обещание.

### 2. Запросы
Придумай 1–3 формулировки того, **что человек набирает в поиск, чтобы найти именно такой ролик**: тема + задача зрителя, не пересказ
сценария и не название «из головы» («fl studio на mac», а не «моя битва с установкой»). Если ролик не про то, что люди ищут, честно напиши об этом в `notes`.

### 3. Данные
```bash
uv run --script $S/research.py "fl studio на mac" "как установить fl studio на macbook" --format shorts --out $WD/seo
# --deep   подсказки по алфавиту (больше фраз, дольше)
# --top 20 сколько конкурентов на запрос
# --cookies-from-browser chrome   если YouTube просит войти (режим без ключа)
```
Получишь `seo_research.md` (читай) и `seo_research.json` (нужен валидатору): подсказки с рангом, кандидаты в главный ключ
(сколько названий топа содержат все его слова), слова в названиях конкурентов, теги и хештеги с числом роликов и медианой просмотров,
длины названий и описаний, главы и ссылки, выбивающиеся ролики. Если конкурентов меньше 5 или деталей меньше 60%, выводы слабые: скажи об этом пользователю и
попробуй другой запрос или `--format long`.

### 4. Пакет → `seo.json`
Прочитай `seo_research.md` целиком и пиши только из него и из расшифровки.
- **Главный ключ:** фраза из «Что люди набирают» с самым высоким рангом и `Названий конкурентов > 0`, которую ролик **действительно закрывает**. Не подходит по смыслу, значит берёшь следующую.
- **Название:** до 100 символов (правило автора, `adhd-shorts/references/package.md`): главный ключ в первых ~40 символах (столько видно
  в ленте). **Шортс** — в конце 2–3 хештега из таблицы хештегов отчёта, `#shorts` в название не ставим. **Длинное видео — без хештегов
  в названии** (на YouTube так принято только у шортсов; автор, 2026-10-22), его хештеги — только в описании. Три варианта с `angle`:
  `search` (ясно называет тему, ключ в начале), `intrigue`/`result`/`emotion` (для ленты, но ролик должен отдать обещанное). Нужен хотя бы один `search`.
  Орфография без ошибок. Капс — максимум одно слово, эмодзи 0–1.
- **Описание:** первые 150 символов — главный ключ + суть + что получит зритель (это сниппет). Дальше 2–4 строки связным текстом, в которые естественно входят
  смежные фразы из подсказок и названий топа (не списком ключей). Для `long` — объёмнее (источники советуют 150–300 слов), с главами от `0:00`, если они есть, и ссылкой на
  следующий ролик или плейлист. Конкретные факты (версии, цены, цифры) бери только из расшифровки.
  **Ссылок в описании нет** (телега, GitHub — словами, без URL): у канала автора закрыты внешние ссылки, YouTube их не пропускает
  без «расширенной проверки» канала (2026-10-22). Валидатор считает URL ошибкой; когда откроют — `--allow-links`.
- **Хештеги** (`hashtags` — строка под описанием): `#shorts` для шортса и тематические из таблицы хештегов отчёта — чем больше роликов топа их используют, тем лучше.
  Если таблица пуста (мало деталей), берёшь слитные формы главных фраз подсказок. Валидатор проверяет все хештеги: из списка, из названия и из описания;
  вместе их не больше 15. Хештеги для TikTok и Reels не пишем: автор публикует только на YouTube.
- **Теги:** варианты написания, синонимы, смежные фразы из подсказок, тегов и названий топа, 8–15 штук, главный ключ первым. Теги мало влияют на поиск, это не место для творчества.
- **Закреп:** вопрос к зрителю по теме ролика.
- **notes:** что слабо подтверждено, чего угадывал, что пришлось исключить.

Формат — `assets/seo.example.json`.

### 5. Проверка
```bash
uv run --script $S/validate.py $WD/seo.json --research $WD/seo/seo_research.json --transcript $WD/words_out.json --md "$ПАПКА/youtube.md"
```
Возврат 0 — можно отдавать. Возврат 1 — исправь пакет и запусти снова. Ошибки:
- превышены лимиты YouTube (название > 100, описание > 5000 байт, теги > 500 символов, хештегов > 15);
- главного ключа нет в названии или в первых 150 символах описания;
- хештег или тег нигде не подтверждён: убери его или замени на найденный в отчёте;
- ключ не найден в подсказках и названиях топа: выбери из таблицы.

Предупреждения читай и решай: «только расшифровка» (термин сказан в ролике, но поиск его не подтверждает), число не найдено в данных, нет поискового варианта.
**Не правь `seo_research.json` и не ослабляй валидатор, чтобы пройти проверку.** Если проверка не проходит, значит данные против твоего текста.

`youtube.md` получается в том же формате, что в `adhd-shorts/references/package.md`, плюс раздел «Основание»: таблица «термин → вердикт → откуда взят».

### 6. Сдача
Коротко скажи: главный ключ и почему он, откуда данные (API или yt-dlp, сколько конкурентов, какая доля деталей), что отброшено валидатором, что в пакете слабо подтверждено.
Не обещай рост просмотров: данные показывают, как упаковаются ролики из топа, а не что именно их подняло.

## Связь с adhd-shorts

`adhd-shorts` вызывает этот скилл на шаге упаковки (SKILL.md §6) вместо того, чтобы писать название, описание, хештеги и теги самому: на вход идут `words_out.json` и хук из `fx.json`,
на выходе — `youtube.md` в его формате. Обложку и `thumbnail-prompt.md` по-прежнему делает `adhd-shorts` (`references/package.md`); её заголовок не повторяет название ролика.
Для длинного разбора и шортсов из него запускай скилл отдельно на каждый ролик: у полного видео и каждого шортса свой главный ключ, `--format long` или `shorts`.

## Грабли

- **Подсказки зависят от языка и страны.** Задавай `--lang`/`--region` под аудиторию, не под язык интерфейса.
- **Режим без ключа может отдать 0% деталей.** Это защита YouTube, а не ошибка скрипта. Подожди, возьми ключ или `--cookies-from-browser`.
- **Совпадение терминов — по грубой основе слова** (эвристика, не морфология). Редкие формы могут не совпасть: тогда впиши фразу так, как она стоит в отчёте.
- **Выбросы из отчёта не копируй.** Их название смотри как паттерн, а не как текст: чужие заголовки не переписываем.
- **Дата отчёта в `seo_research.json`.** Через пару недель выдача меняется: для нового ролика запускай заново.
