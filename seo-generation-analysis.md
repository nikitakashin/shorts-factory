# Как в shorts-factory генерируется SEO / упаковка для YouTube

Разбор по коду репозитория (ветка `master`, коммит `3498a7a`). Нужен как эталон для сравнения с другим подходом.

## 0. Главный факт

**Кода, который генерирует SEO, нет.** Нет скрипта, API-вызова, парсинга выдачи YouTube/Google Trends, подсказок поиска, конкурентного анализа. Вся «генерация» — это инструкция для LLM-агента (Claude) в markdown-файле, который он читает на шаге «Упаковка» и сам пишет `youtube.md` по шаблону.

| Где | Что там |
|---|---|
| [`skills/adhd-shorts/references/package.md`](skills/adhd-shorts/references/package.md) | **Единственный источник правил SEO**: шаблон `youtube.md` + правила названия + шаблон промпта обложки |
| [`skills/adhd-shorts/SKILL.md`](skills/adhd-shorts/SKILL.md) §6 «Упаковка», §«Длинный разбор», §«Грабли» | Когда вызывать упаковку, что подавать на вход, запрет выдумывать факты |
| [`skills/adhd-shorts/references/style.md`](skills/adhd-shorts/references/style.md) §«Первая секунда» | Не SEO, но влияет на то же (удержание → охват); правила хука |
| [`skills/adhd-shorts/scripts/thumb_frames.py`](skills/adhd-shorts/scripts/thumb_frames.py) | Единственный код упаковки: выбор кадров для обложки |

## 2. Правила (дословно из кода/доков, в сжатом виде)

### 2.1. Название (Shorts / TikTok)
- ≤ 50 символов; главное слово — в первых 3–4 словах (обрезается в ленте).
- Интрига без кликбейта, который ролик не отдаёт: развязка совпадает с обещанием.
- Капс — максимум одно слово; эмодзи — 0–1.
- Не повторять название в первой строке описания слово в слово.
- Первая строка описания — без спойлера развязки.

### 2.2. Достоверность
- Факты — только из расшифровки и кадров; ничего не выдумывать (версии, даты, цены — как сказано или видно на экране). package.md:3, SKILL.md «Грабли».
- В `Заметках` фиксируется, что угадывалось (имена, цифры, неразборчивое).

### 2.3. Хук (влияет на охват, живёт в `fx.json`, не в `youtube.md`)
- Обязательная плашка с главной мыслью с кадра 0–2.6 с: конфликт или результат, **не вопрос**, ≤ 2 строк по ~14 символов.
- Первый кадр — резкое лицо крупно; звук на кадре 0.
- Обоснование из практики автора: у первого шортса «Продолжили смотреть» 49.6% при досмотре 71% — уходили в первую секунду.

### 2.4. Обложка
- Одна обложка на каждый публикуемый ролик (полное видео 16:9 + каждый шортс 9:16 — отдельные промпты и заголовки).
- Кадр: `thumb_frames.py` — кандидаты с моментов акцентов (стикеры, punch, shake, boom) + кадр каждые 2.5 с; из каждого окна ±0.35 с берётся самый резкий (дисперсия лапласиана); отбрасываются кадры без лица (Haar-каскад OpenCV); акценты идут вперёд, затем самые крупные лица; по умолчанию 8 штук. Человек выбирает 1–2 по листу: открытые глаза, яркая эмоция, лицо резкое, без смаза.
- Заголовок: ≤ 2 строк по ~14 символов, конфликт или результат, не вопрос, не дублирует название слово в слово.
- Текст — в промпте слово в слово, в кавычках, + фраза «Text must be spelled exactly as written»; служебные пометки («наклон 4°», «#») в промпт не писать — нейросеть их нарисует.
- Бренды описывать словами, без логотипов.
- 9:16: заголовок сверху (низ закрыт интерфейсом Shorts); 16:9: человек справа, текст слева.
- Фиксированный стиль промпта: жёлтый `#FFE500` текст с чёрной обводкой, красная `#E61E28` плашка, насыщенные цвета, rim light, fisheye, speed lines; негативный промпт задан.
- Заставка в конце шортса (`endcard`) — обложка полного видео; в публикации напомнить автору указать «Связанное видео».

## 3. Выводы из кода (сильные и слабые стороны)

### Сильные стороны
1. **Привязка к реальному содержимому**: текст строится по расшифровке и кадрам, плюс явный запрет на выдумки → низкий риск вранья в метаданных.
2. **Согласованность пакета**: заголовок обложки, хук и название разведены по ролям (не дублируют друг друга).
3. **Выбор кадра обложки автоматизирован** и измеряем (резкость + лицо + акцент).
4. **Правила усечения под ленту** (≤ 50 символов, главное слово в начале) учитывают реальный UI Shorts.
5. **Раздельные обложки/хештеги** под формат и платформу (9:16 vs 16:9; Shorts/TikTok/Reels).
6. **Хук как часть упаковки** с обоснованием по собственной статистике канала.

### Слабые стороны / пробелы
1. **Нет keyword research**: ни подсказок YouTube/Google, ни частотности, ни конкурентов — ключевые слова берутся «из головы» модели и из речи автора.
2. **Нет проверки по выдаче и трендам**: хештеги `#fyp`, `#рекомендации` зашиты как константы.
3. **Нет валидации** ограничений (≤ 50 символов, 3–5 хештегов, 10–15 тегов) — только текстовое правило для LLM.
4. **Нет A/B тестирования** названий/обложек: 3 варианта названия дают на выбор, но выбор и результат не логируются.
5. **Нет петли обратной связи**: метрики не попадают в правила автоматически (единственный ориентир — «Продолжили смотреть» 60–70%+, «ориентир авторов шортсов, не официальная норма»).
6. **Не описаны** длина описания в символах, первые 100–150 символов как сниппет, ссылки/CTA, субтитры-файл (.srt), язык/категория видео, плейлисты, главы (для длинного видео).
7. **Теги YouTube** формулируются без правил приоритета (вес тегов в ранжировании мал, а правила тратят на них слот).
8. **Тематика зашита под одну нишу автора** (примеры про FL Studio, Mac, Авито) и под его стиль обложек (жёлтый/красный, fisheye) — не универсально.
9. **Контент-политика**: нет правил про мат в названии/описании (в субтитрах цензурится, в метаданных не оговорено), про disclaimers/спонсорство.
10. Правила в `package.md` частично расходятся с практикой: в описании сразу идут «хештеги одной строкой», а в разделе «Хештеги» они повторяются по платформам — не указано, какой набор попадает в описание на YouTube.

## 4. Шаблон `youtube.md` (структура вывода)

```
# <Название основное>
## Варианты названия   (3 шт.: интрига / результат / эмоция)
## Описание            (2–4 строки + хештеги одной строкой)
## Хештеги             (Shorts / TikTok / Reels)
## Теги YouTube        (10–15, через запятую)
## Закреплённый комментарий
## Заметки             (длительность, угадано, мат, звук)
```
